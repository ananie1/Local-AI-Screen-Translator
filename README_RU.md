# Local AI Screen Translator 2.0 (RU)

🌐 **Язык:** [English](README.md) | [Русский](README_RU.md)

## Обзор

Local AI Screen Translator — это легковесная модульная утилита, которая захватывает любую область экрана, распознаёт на ней текст (OCR) и переводит его на русский язык с помощью языковой модели. Модель может работать локально (LM Studio, Ollama) или подключаться через любой OpenAI-совместимый API по ключу.

Программа работает на уровне операционной системы, а не внутри браузера, поэтому подходит и для видеоигр, и для десктопного софта, зарубежных сайтов, медиаплееров и документов. Само приложение ничего никуда не отправляет, кроме одного запроса к указанному вами LLM-серверу.

## Принцип работы

```text
Выделение области  →  OCR  →  Запрос к LLM  →  Оверлей с переводом
 screen_selector   ocr_engine  llm_client        overlay
                   (всё связывает main)
```

1. **Захват.** Делается снимок всего рабочего стола и показывается «замороженным», вы выделяете мышью прямоугольник с текстом.
2. **OCR.** Вырезанный фрагмент распознаёт [RapidOCR](https://github.com/RapidAI/RapidOCR) (ONNX Runtime, CPU).
3. **Перевод.** Текст отправляется на `/v1/chat/completions` с системным промптом, требующим вывести только перевод.
4. **Вывод.** Результат появляется в безрамочном, полупрозрачном окне поверх всех окон рядом с выделенной областью.

OCR и сетевой запрос выполняются в отдельном потоке, поэтому интерфейс не зависает.

## Ключевые особенности

- Выделение области как в «Ножницах» (поддержка нескольких мониторов и HiDPI).
- Никаких внешних OCR-программ: всё ставится через `pip`.
- Любой OpenAI-совместимый сервер: LM Studio, Ollama, OpenAI и другие.
- Оверлей: перетаскивание, копирование, сворачивание, закрытие (`Esc`).
- Поддержка «думающих» моделей: блоки `<think>…</think>` вырезаются из ответа.
- Настройки подключения сохраняются между запусками.
- Модульная архитектура: у каждого модуля одна зона ответственности, любой можно заменить отдельно.

## Системные требования

- Python 3.10–3.12.
- Запущенный сервер LLM с загруженной моделью (например, LM Studio на `http://localhost:1234`) либо API-ключ совместимого сервиса.
- Windows, macOS или Linux (X11). См. [Ограничения и подводные камни](#ограничения-и-подводные-камни).

## Установка

```bash
git clone https://github.com/ananie1/Local-AI-Screen-Translator.git
cd Local-AI-Screen-Translator
python -m venv .venv
# Windows:      .venv\Scripts\activate
# Linux/macOS:  source .venv/bin/activate
pip install -r requirements.txt
```

## Использование

```bash
python main.py
```

1. Запустите сервер LLM и загрузите модель.
2. В окне программы укажите **URL**, **API-ключ** (если нужен) и **название модели**.
3. Нажмите **«Выделить область и перевести»**.
4. Выделите текст мышью. `Esc` или правая кнопка мыши отменяют выделение.
5. Перевод появится над областью (под ней, если сверху нет места).

### Настройка подключения

| Сервис    | URL                                          | API-ключ | Модель                            |
|-----------|----------------------------------------------|----------|-----------------------------------|
| LM Studio | `http://localhost:1234/v1/chat/completions`  | не нужен | любое (`local-model`)             |
| Ollama    | `http://localhost:11434/v1/chat/completions` | не нужен | точное имя из `ollama list`       |
| OpenAI    | `https://api.openai.com/v1/chat/completions` | нужен    | например, `gpt-4o-mini`           |

### Что можно менять

- **Целевой язык и поведение модели:** `SYSTEM_PROMPT` в `llm_client.py`.
- **Таймаут и температура:** значения по умолчанию в `LLMConfig` (`llm_client.py`): 120 с и 0.2.
- **OCR-движок:** замените тело `OcrEngine.recognize()` в `ocr_engine.py`. Остальному приложению нужен лишь метод, который принимает изображение PIL и возвращает строку.

## CPU, GPU и производительность

- Встроенный OCR работает только на **CPU**. Видеокарта не нужна и здесь пользы не даёт.
- LLM — отдельный компонент. Будет ли она использовать CPU или GPU, зависит только от настроек вашего сервера (LM Studio, Ollama) и модели.
- На практике перевод моделью обычно занимает заметно больше времени, чем OCR, поэтому узким местом OCR бывает редко.
- Чем больше выделенная область, тем дольше распознавание и перевод. Выделяйте только нужный текст.

## Ограничения и подводные камни

**OCR**

- Стандартные модели RapidOCR распознают латиницу и китайский, но **не кириллицу и не японский**. Программа рассчитана на перевод *на* русский, например, с английского.
- Мелкий, малоконтрастный или стилизованный текст (игровые шрифты, текст на пёстром фоне) может распознаваться плохо. Ошибки OCR попадают прямо в перевод.
- Текст в несколько колонок может перемешаться, потому что строки сортируются сверху вниз, затем слева направо. Выделяйте по одной колонке.
- Вертикальный и сильно повёрнутый текст не поддерживается.
- Первый вызов OCR после запуска медленнее остальных: модель загружается лениво.

**Захват экрана**

- Игры в **эксклюзивном полноэкранном режиме** и защищённое DRM-видео (некоторые стриминговые сервисы) могут давать чёрный скриншот, а оверлей может не показываться поверх них. Используйте оконный режим или окно без рамки.
- При разном масштабе (DPI) на разных мониторах границы области могут слегка смещаться.
- macOS: выдайте приложению (терминалу или IDE, из которых оно запущено) разрешение **«Запись экрана»**.
- Linux: на Wayland захват через `mss` может не работать, используйте сессию X11.

**LLM**

- Сервер должен быть запущен, а модель загружена. Иначе будет ошибка подключения или HTTP 404.
- В Ollama имя модели должно в точности совпадать с выводом `ollama list`.
- Небольшие локальные модели иногда добавляют комментарии или отказываются отвечать, хотя промпт требует только перевод. Попробуйте модель побольше или с обучением на инструкциях.
- Первый запрос к локальной модели может идти долго (она загружается в память). Таймаут — 120 секунд.
- Очень длинный текст отправляется одним запросом и может не поместиться в контекст модели.

**Безопасность и конфиденциальность**

- С локальной LLM текст не покидает ваш компьютер. С внешним API **распознанный текст отправляется этому провайдеру**.
- API-ключ хранится в настройках приложения (`QSettings`, в Windows это реестр) в открытом виде. Не используйте ключ без лимита расходов.
- Скриншот хранится только в памяти на время одного запроса и на диск не записывается.

## Решение проблем

| Симптом                                  | Вероятная причина и решение                                                 |
|------------------------------------------|-----------------------------------------------------------------------------|
| «Не удалось подключиться к …»            | Сервер не запущен, неверный порт или URL.                                   |
| HTTP 404 / модель не найдена             | Модель не загружена или имя указано неверно.                                |
| HTTP 401 / 403                           | Нет или неверный API-ключ.                                                  |
| «Текст в выделенной области не найден»   | Слишком мелкий или бледный текст, либо неподдерживаемое письмо (кириллица, японский). |
| Чёрный фон при выделении                 | Эксклюзивный полноэкранный режим или защищённый контент, см. выше.          |
| Пустой или странный перевод              | Модель слишком маленькая или «думающая», попробуйте другую.                 |
